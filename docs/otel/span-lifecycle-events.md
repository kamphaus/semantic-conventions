## Overview

SDKs export a span when it ends. Span lifecycle events make a span visible
while it runs, and let consumers build the span even if it never reaches a
trace exporter. Each span that has lifecycle events enabled emits:

| Event | Emitted | Carries |
| --- | --- | --- |
| [`otel.span.started`](#event-otelspanstarted) | when the span starts | the span's type, name, kind, parent, TraceState and sampling-relevant attributes |
| [`otel.span.progress`](#event-otelspanprogress) | periodically, and/or when the span changes | what changed since the previous lifecycle event |
| [`otel.span.ended`](#event-otelspanended) | when the span ends | the complete span |

All lifecycle events of a span:

- are emitted with the span's trace ID, span ID and trace flags as their trace
  context, and with the span's resource and instrumentation scope;
- record the span's own attributes as event attributes, with unchanged keys
  and values;
- are only emitted for sampled spans.

## Merge rules

A consumer builds a span by merging all lifecycle events that share a trace ID
and span ID.

1. **Fixed fields** are set when the span is created and cannot change: trace
   ID, span ID, parent span ID, kind, start time, span type and TraceState.
   Every event that carries one of them MUST carry the same value.
2. **Changeable fields** are the name and the attributes. They are merged per
   key: the value from the event with the later timestamp wins.
3. **Nothing is removed.** A key missing from an event means "unchanged or
   unknown", never "removed".
4. **`otel.span.ended` is final.** Its values win over those of any earlier
   event, regardless of the order in which events arrive. Status and end time
   come only from `otel.span.ended`.
5. **Merging is idempotent.** Receiving the same event twice doesn't change
   the result.

| `otel.span.ended` compared to earlier events | Result |
| --- | --- |
| carries more attributes | added |
| carries fewer attributes | the earlier ones are kept |
| carries a different value | the value from `otel.span.ended` |
| carries a different fixed field | the value from `otel.span.ended`; the consumer SHOULD report the inconsistency |

The event name MUST be `otel.span.started`.

Reports that a span has started.

The event MUST be emitted with the span's trace ID, span ID and trace
flags as its trace context. Its timestamp MUST be the span's start time.

Besides the attributes listed below, the event MUST carry the span's
sampling-relevant attributes, as defined by the semantic convention the
span follows, and MAY carry any other attribute the span has when it
starts. The span's attributes are recorded as event attributes with
unchanged keys and values.

See [span lifecycle events](/docs/otel/span-lifecycle-events.md) for how
consumers combine this event with the other lifecycle events of the
same span.

### Event: `otel.span.progress`

**Status:** ![Development](https://img.shields.io/badge/-development-blue)

The event name MUST be `otel.span.progress`.

Reports that a span is still running, and what changed since the previous lifecycle event for the same span.

The event MUST be emitted with the span's trace ID, span ID and trace
flags as its trace context. Its timestamp is the time the event was
emitted.

The event SHOULD only carry the span attributes that were added or
changed since the previous lifecycle event for the same span. An event
without changes (a heartbeat) carries no span attributes. A missing
attribute means unchanged or unknown, never removed.

See [span lifecycle events](/docs/otel/span-lifecycle-events.md) for how
consumers combine this event with the other lifecycle events of the
same span.

**Status:** ![Development](https://img.shields.io/badge/-development-blue)

The event name MUST be `otel.span.ended`.

Reports that a span has ended, and carries the complete span.

The event MUST be emitted with the span's trace ID, span ID and trace
flags as its trace context. Its timestamp MUST be the span's end time.

The event MUST carry all of the span's attributes, recorded as event
attributes with unchanged keys and values. A consumer MUST be able to
build the span from this event alone, without any other lifecycle
event.

See [span lifecycle events](/docs/otel/span-lifecycle-events.md) for how
consumers combine this event with the other lifecycle events of the
same span.
